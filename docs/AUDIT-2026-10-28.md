# Repository Audit — 2026-10-28

Tools: `tsc` (src + tests), ESLint, Vitest/Jest (incl. DB suites on a real
Postgres-compatible engine), `npm audit`, Semgrep/njsscan rules,
detect-secrets, Knip, markdownlint, repo `evals/check.js`, manual review.
Plan: `plans/008-repo-audit-cleanup.md`.

## Fixed (verified)

### P0

- **Auth validation rejected every request.** `validateBody` parsed the raw
  body against `z.object({ body: ... })` schemas, so register, login,
  refresh, and preferences all returned 400 `body: Required`. Now wraps the
  body; regression tests + `eval-011` guard it.
- **Seed could create admin/staff demo accounts (`password123`) in
  production.** `seed.ts` now refuses when `NODE_ENV=production`, and the
  `seed:prod` script is removed.

### P1

- `GET /reservations` 500: `reservations.created_at` never existed
  (migration `007` adds it).
- `POST /blocks` 500: `blocks.reason_ar` never existed (migration `007`);
  `GET /blocks` 500: `VARCHAR = UUID` join now casts.
- Experiences created via API were stuck in `draft` (INSERT omitted
  `plan_state`) — invisible and unbookable.
- `experience.update()` interpolated caller-controlled keys into SQL:
  now a column whitelist with camelCase normalization (same for
  reservation `updateState` extra fields).
- Payment model: no duplicate-intent guard, `completed_at` never set,
  refunds never recorded amount/status/timestamp.
- Audit POST with missing fields returned 500 instead of 400; staff state
  updates returned 500 instead of 400 for invalid transitions; assign-host
  returned 500 for unknown/malformed host IDs.
- DB test suites (`api`, `models`, `e2e`: 285 tests) had never run in CI and
  were almost entirely red: broken test setup (per-test wipes, pool ended
  mid-file, missing tables, rate limits), stale contracts, real Stripe
  network calls. All revived (Stripe is now an in-memory double) and CI
  runs them serially.
- Prod dependency vulns: `body-parser`, `qs`, `zod` (migrated Zod 3 → 4),
  `vite`, `source-map-js`. `npm audit --omit=dev` is 0 for both apps and CI
  now blocks on `high` (was `critical` despite the step name).
- docker-compose backend could not start (production image + `tsx watch`):
  now builds the `builder` target for dev.
- Node 20 (EOL) → 22 everywhere; PostgreSQL 15 (EOL) → 17.
- CI: fake echo-only deploy jobs removed; actions pinned to SHAs;
  Dependabot and CodeQL added; test typechecking enforced (`ts-jest`
  diagnostics are off, so test type rot was invisible — 194 errors, now 0).

### P2 / cleanup

- JWT algorithms pinned to HS256; CORS/rate-limit config now actually wired
  (was hardcoded, config unused); request logger uses Winston, not `console`.
- Dead code removed: legacy `host.controller`, unused `src/shared/` tree,
  unused barrel files, redundant direct `axe-core`, unused
  `validateQuery`/`validateParams`.
- PWA manifest/HTML referenced 7 missing PNGs, a fake IARC id, a dead
  protocol handler, and nonexistent routes; icons/OG image generated from
  the logo and manifest/sitemap/robots now reflect reality.
- Nginx: security headers (incl. CSP), gzip, immutable asset caching,
  no-cache for `index.html`/`sw.js`, healthcheck, pinned image.
- Statistics COUNTs cast to `int` (were strings via `pg`); audit pagination
  made stable (`timestamp, id` ordering); `Payment` type completed.
- Docs drift: Redis was documented as wired (it is not; issue 014),
  API.md listed two nonexistent auth endpoints, README test commands.

## Deferred (noted, not fixed)

- No frontend linter (backend ESLint 8 is EOL-line) and 265 `any` usages.
  Recommend one ESLint 9 flat config for both apps; fix `any` gradually.
- No URL routing or deep links in the SPA (view state only) — SEO/UX gap.
- `/metrics` is unauthenticated (memory/CPU only, no DB internals); put it
  behind network controls or a token in production.
- Payments: controller blocks any second payment attempt after a failed
  one (409 forever); model now allows retry after `failed`, align the
  controller.
- Most non-auth POST routes lack Zod body schemas (controllers validate
  manually, inconsistently). Add schemas endpoint by endpoint.
- Notification "read" is modeled as delivery state; no real email/SMS/push
  providers yet (tracked in `.github/ISSUES/002`, `003`, `016`).
- Migrations have no tracking table/transactions per file; they rely on
  `IF NOT EXISTS` idempotency.
- `req.query` assignment in sanitization works on Express 4 but will break
  on Express 5 — handle during that upgrade.
- Coverage: FE ~68% lines (`useAuth` 18%, `ExperienceDetails` 17%,
  `Staff` 39%). One backend model test (`findByPhone`) intermittently hits
  a transport reset on the single-connection local test engine; it passes
  in isolation — CI on real PostgreSQL is the ground truth.
